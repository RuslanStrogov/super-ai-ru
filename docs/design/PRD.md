# Product Requirements Document (PRD)

> **Продукт:** AI Super Assistant — российский аналог Abacus.ai  
> **Статус:** MVP  
> **Версия:** 1.0.0  
> **Дата:** 2026-07-09  

---

## 1. Executive Summary

**AI Super Assistant** — это единая платформа для доступа к ведущим языковым моделям (LLM), инструментам Retrieval-Augmented Generation (RAG) и простым AI-агентам. Продукт решает проблему фрагментированного доступа к AI-инструментам на российском рынке, где отсутствуют полноценные аналоги зарубежных платформ (Abacus.ai, ChatGPT Enterprise, Poe).

MVP объединяет в одном интерфейсе:
- Шлюз к десяткам LLM (OpenAI, YandexGPT, GigaChat, DeepSeek, Llama и др.)
- Мульти-модельный чат с переключением между моделями
- RAG-движок для загрузки, индексации и поиска по документам
- Простую систему AI-агентов
- Панель администратора

**Техстек:** Python FastAPI + Go, Next.js + React, Qdrant + PostgreSQL, MLflow, LiteLLM, vLLM, Tauri (desktop), Yandex Cloud.

**Целевая аудитория:** фрилансеры, ML-инженеры, владельцы малого и среднего бизнеса, Enterprise-заказчики.

## 2. Problem Statement

### 2.1. Дефицит AI-платформ в РФ

Российский рынок испытывает острый дефицит интегрированных AI-платформ. Зарубежные решения (Abacus.ai, ChatGPT Enterprise, Anthropic Console, Poe):

- **Недоступны** для оплаты из РФ
- **Блокируют** российских пользователей по IP
- **Не поддерживают** российские LLM (YandexGPT, GigaChat)
- **Не отвечают** требованиям 152-ФЗ о персональных данных

### 2.2. Фрагментация инструментов

Пользователи вынуждены использовать 5–10 разных сервисов:

| Задача | Инструмент |
|--------|-----------|
| Чат с GPT | ChatGPT |
| Чат с YandexGPT | Yandex 300 |
| Чат с GigaChat | Сбер |
| Работа с документами + AI | Отдельные RAG-решения |
| AI-агенты | LangChain + ручная сборка |
| Логирование | Отсутствует |

### 2.3. Отсутствие единого API

Разработчики не имеют единого API для работы с российскими и зарубежными LLM — каждая модель требует отдельной интеграции, отдельного ключа, отдельного биллинга.

### 2.4. Проблемы с данными

- Нет централизованного хранения истории запросов
- Нет инструментов для работы с корпоративными документами
- Нет контроля доступа на уровне команды/организации

## 4. MVP Features

### 4.1. Epic 1: LLM Gateway

> **Единый API-шлюз ко всем моделям**

**User Stories:**

- **Как ML-инженер,** я хочу отправлять запросы к любой модели через единый OpenAI-совместимый эндпоинт, чтобы не писать отдельную интеграцию для каждого провайдера.
- **Как фрилансер,** я хочу видеть все доступные модели в одном списке с понятными названиями, чтобы выбирать подходящую под задачу.
- **Как владелец SMB,** я хочу устанавливать лимиты на запросы по моделям и пользователям, чтобы контролировать расходы.
- **Как администратор,** я хочу подключать/отключать провайдеров через конфиг без перезапуска сервиса, чтобы оперативно управлять доступностью моделей.

**Функциональные требования:**

| # | Требование | Приоритет |
|---|-----------|-----------|
| F1.1 | OpenAI-совместимый REST API (`/v1/chat/completions`) | P0 |
| F1.2 | Поддержка провайдеров: OpenAI, YandexGPT, GigaChat, DeepSeek, Anthropic, Ollama (локальные модели) | P0 |
| F1.3 | Проксирование с автоматической маршрутизацией (primary → fallback) | P1 |
| F1.4 | Кэширование повторяющихся запросов (TTL-конфигурируемое) | P1 |
| F1.5 | Rate limiting — per-user, per-model, per-provider | P0 |
| F1.6 | Мониторинг времени ответа и ошибок по каждому провайдеру | P1 |
| F1.7 | Логирование всех запросов/ответов с возможностью поиска | P0 |

**Техническая реализация:** LiteLLM (прокси) + FastAPI (обёртка).

## 6. Out of Scope

Следующие возможности **НЕ входят** в MVP и будут рассмотрены в последующих версиях:

| # | Возможность | Причина исключения |
|---|------------|-------------------|
| O1 | **Fine-tuning моделей** — дообучение LLM на пользовательских данных | Высокая сложность, требуется GPU-инфраструктура |
| O2 | **Маркетплейс агентов** — публикация и продажа агентов пользователями | Требует moderation-пайплайн и биллинг |
| O3 | **Multi-modal (изображения, видео, аудио)** — генерация и распознавание | MVP фокусируется на тексте |
| O4 | **Real-time voice-чат** — голосовое общение с AI | Требует WebRTC + ASR/TTS инфраструктуру |
| O5 | **Workflow Automation** — сложные многомодульные пайплайны агентов | MVP Agent System — только одиночные агенты с инструментами |
| O6 | **On-premise установка** — полный self-hosted дистрибутив | Будет в V1.1 после стабилизации облачной версии |
| O7 | **Мобильное приложение (iOS/Android)** — нативные приложения | MVP — Web + Tauri Desktop; мобильные — в V2 |
| O8 | **Собственная LLM** — дообучение или обучение с нуля | Продукт — агрегатор, не провайдер модели |

## 7. User Flow (MVP)

### 7.1. Основной пользовательский путь

```
[1. Регистрация / Вход]
        │
        ▼
[2. Онбординг — выбор первой модели]
        │
        ▼
[3. Создание нового чата]
        │
        ▼
[4. Отправка сообщения]
        │
        ├──→ [4a. Ответ от выбранной LLM]
        │
        ├──→ [4b. Переключение модели mid-chat → новый ответ]
        │
        ▼
[5. Загрузка документа (drag-and-drop)]
        │
        ▼
[6. Автоматическая индексация в RAG]
        │
        ▼
[7. Запрос по документу → ответ с цитатами]
        │
        ▼
[8. Создание агента (опционально)]
        │
        ▼
[9. Экспорт диалога (JSON / Markdown / PDF)]
```

### 7.2. Пошаговое описание

**Шаг 1. Регистрация / Вход**
- Пользователь открывает веб-приложение
- Вводит email и пароль (или через OAuth — Google, Yandex)
- Подтверждает email (ссылка на почту)
- Попадает на главный экран

**Шаг 2. Онбординг**
- Всплывающее окно с предложением выбрать модель по умолчанию
- Краткая демонстрация интерфейса (60 секунд)
- Предложение загрузить первый документ

**Шаг 3. Чат**
- Пользователь видит пустой чат с полем ввода
- Слева — список диалогов
- Сверху — селектор модели (текущая: выбрана на онбординге)
- Ввод сообщения → Enter → потоковый ответ (streaming)

**Шаг 4. Переключение модели**
- Клик на селектор модели → выпадающий список
- Выбор другой модели → диалог продолжается, следующий ответ от новой модели
- Визуальная метка у каждого сообщения: какая модель отвечала

**Шаг 5. Загрузка документа**
- Кнопка «Загрузить документ» / drag-and-drop в область чата
- Прогресс-бар загрузки и индексации
- После завершения: уведомление «Документ проиндексирован, готов к вопросам»

**Шаг 6. RAG-запрос**
- Пользователь пишет вопрос по документу
- Система находит релевантные чанки → формирует промпт с контекстом
- Ответ содержит цитаты: «Согласно разделу 3.2 договора...»
- Клик на цитату → открывается оригинальный документ на месте цитаты

**Шаг 7. Агент**
- Пользователь заходит на вкладку «Агенты»
- Создаёт агента: имя + системный промпт + инструменты (галочки: поиск в документах, веб-поиск, Python)
- Сохраняет → открывается чат с агентом
- Агент выполняет задачи, показывая логи вызовов инструментов

**Шаг 8. Экспорт**
- В меню чата → «Экспорт»
- Выбор формата: JSON (полный лог), Markdown (чистый текст), PDF (с оформлением)
- Файл скачивается

### 7.3. Администраторский путь

```
[Дашборд → Метрики]
       │
       ▼
[Список пользователей]
       │
       ├──→ [Блокировка / Разблокировка]
       ├──→ [Назначение роли]
       │
       ▼
[Логи аудита]
       │
       ▼
[Настройки провайдеров → включение/отключение моделей]
```

## 8. Acceptance Criteria

MVP считается готовым к релизу при выполнении всех следующих критериев:

### 8.1. Функциональные критерии

| # | Критерий | Статус |
|---|---------|--------|
| AC1 | Пользователь может зарегистрироваться, войти и выйти из системы | ☐ |
| AC2 | Пользователь может отправить сообщение минимум 3 различным LLM и получить ответ | ☐ |
| AC3 | Пользователь может переключить модель в середине диалога — новый ответ приходит от новой модели | ☐ |
| AC4 | Пользователь может загрузить PDF-документ, дождаться индексации и задать по нему вопрос — ответ содержит цитату из документа | ☐ |
| AC5 | Пользователь может создать агента с промптом и инструментом «RAG-поиск», запустить диалог и получить ответ, использующий его документы | ☐ |
| AC6 | Пользователь может просмотреть историю своих диалогов | ☐ |
| AC7 | Пользователь может экспортировать диалог в Markdown | ☐ |
| AC8 | Администратор может войти в панель и увидеть дашборд с метриками | ☐ |
| AC9 | Администратор может заблокировать пользователя — тот теряет доступ к API и UI | ☐ |
| AC10 | API Gateway возвращает ответ на запрос к /v1/chat/completions для каждого подключённого провайдера | ☐ |
